# Common errors mapping

> **Not documented** (same for every endpoint, or never surfaced over HTTP):
> - Authentication: `jwtDecodingError`, `invalidClaim`, `missingHeader`, `jwkDecodingError`, `notAllowedPrivateKeyException`, `missingRequiredJWKClaim`, `invalidPublicKey`, `notAllowedCertificateException`, `jwksSigningKeyError`, `tokenVerificationFailed`, `notAllowedMultipleKeysException`, `badBearerToken`, `invalidKeyLength`, `notAnRSAKey`, `badDPoPToken`, `keyTypeNotAllowed`, `invalidJWKClaim`.
> - Middleware-only: —
> - Infrastructure: `authenticationSaslFailed`, `htmlTemplateInterpolationError`, `pdfGenerationError`, `genericError`, `thirdPartyCallError`, `tokenGenerationError`, `missingRSAKey`, `missingKafkaMessageData`, `kafkaMessageProcessError`, `kafkaApplicationAuditingFailed`, `fallbackApplicationAuditingFailed`, `invalidSqsMessage`, `decodeSQSMessageError`, `pollingMaxRetriesExceeded`.
>
> Processes covered: `tenant-process`.

## `operationForbidden`

Insufficient privileges.

| Process | BFF endpoint | When it happens | Reachable from the FE? | Steps to reproduce (UI) | Resolution steps |
| ------- | ------------ | --------------- | ---------------------- | ----------------------- | ---------------- |
| `tenant-process` | `POST /tenants/:tenantId/mails` | The path tenant ID differs from the authenticated UI tenant's organization ID; `assertRequesterAllowed` in `TenantService.addTenantMail` throws `operationForbidden`. | Cannot happen — `UpdatePartyMailDrawer` sends `jwt.organizationId` as `partyId`, and `TenantServices.updateMail` places that same value in the BFF path. | — | — |
| `tenant-process` | `DELETE /tenants/:tenantId/mails/:mailId` | The path tenant ID differs from the authenticated UI tenant's organization ID; `assertRequesterAllowed` in `TenantService.deleteTenantMailById` throws `operationForbidden`. | Cannot happen — the frontend has no delete-mail service or control; `PartyContactsSection` opens `UpdatePartyMailDrawer`, which only issues the POST endpoint. | — | — |
| `tenant-process` | `POST /tenants/delegatedFeatures/update` | The authenticated tenant has no active certified attribute whose ID equals `DELEGATIONS_ALLOWED_ATTRIBUTE_ID`, and `FEATURE_FLAG_DELEGATION_CONSTRAINT_SKIP` is false; `assertTenantAllowedForDelegation` in `TenantService.updateTenantDelegatedFeatures` throws `operationForbidden`. | **CAN HAPPEN** — `AuthGuard` checks eligibility when entering `/aderente/deleghe`, but the drawer does not re-check before saving. If a certifier revokes the attribute while the admin's page remains open, the stale page can still submit and the process checks the current tenant state. | **Data precondition:** tenant A has an admin user and the active certified attribute configured by `DELEGATIONS_ALLOWED_ATTRIBUTE_ID`; `FEATURE_FLAG_DELEGATION_CONSTRAINT_SKIP=false`. Tenant C is the certifier for that attribute and has assigned it to A.<br>1. As tenant A's admin, open `/aderente/deleghe` and select _Disponibilità_.<br>2. Leave that page open. In a separate session, sign in as a tenant C admin and open `/aderente/certificatore` → _Assegnazione attributi_.<br>3. Find A's delegation-eligibility attribute, choose _Revoca attributo_, select _Confermo di aver compreso le conseguenze della revoca_, and confirm with _Revoca_.<br>4. In a fresh tenant A session, open `/aderente/anagrafica` and wait until the configured attribute is no longer listed; keep the original Delegations page open.<br>5. In A's original session, choose _Modifica_, change either _Delega alla fruizione_ or _Delega all’erogazione_, then choose _Aggiorna_. The save is the defect step: the route guard's earlier eligibility result is not checked again. | 🟡 **Medium resolution**<br>1. Ask tenant C's certifier to assign the active attribute configured by `DELEGATIONS_ALLOWED_ATTRIBUTE_ID` to tenant A again.<br>2. Alternatively, an operator can set `FEATURE_FLAG_DELEGATION_CONSTRAINT_SKIP=true` for `tenant-process` and apply the configuration change --- **This is possible, but should never happen**---. |

## `unauthorizedError`

Unauthorized.

| Process | BFF endpoint | When it happens | Reachable from the FE? | Steps to reproduce (UI) | Resolution steps |
| ------- | ------------ | --------------- | ---------------------- | ----------------------- | ---------------- |
| `tenant-process` | `GET /consumers` | The caller has none of `ADMIN_ROLE`, `API_ROLE`, `SECURITY_ROLE`, `SUPPORT_ROLE`, or `VIEWER_ROLE`; `validateAuthorization` in `TenantRouter`'s `getConsumers` handler throws `unauthorizedError`. | Cannot happen — callers are the `PROVIDE_ESERVICE_LIST` and `PROVIDE_PURPOSE_LIST` routes; their `authLevels` are all accepted by this handler's `validateAuthorization`. | — | — |
| `tenant-process` | `GET /producers` | The caller has none of `ADMIN_ROLE`, `API_ROLE`, `SECURITY_ROLE`, `SUPPORT_ROLE`, `VIEWER_ROLE`, or `REVIEWER_ROLE`; `validateAuthorization` in `TenantRouter`'s `getProducers` handler throws `unauthorizedError`. | Cannot happen — the catalog and consumer-purpose routes that call this endpoint admit only roles included in the handler's `validateAuthorization` list. | — | — |
| `tenant-process` | `GET /tenants` | The caller has none of `ADMIN_ROLE`, `API_ROLE`, `SECURITY_ROLE`, `SUPPORT_ROLE`, `M2M_ROLE`, `M2M_ADMIN_ROLE`, `VIEWER_ROLE`, or `REVIEWER_ROLE`; `validateAuthorization` in `TenantRouter`'s `getTenants` handler throws `unauthorizedError`. | Cannot happen — `CREATE_DELEGATION`, `TENANT_CERTIFIER`, and `ASSISTENCE_PARTY_SELECTION` admit only roles accepted by this handler; the tenant-certifier assignment controls are additionally admin-only. | — | — |
| `tenant-process` | `GET /tenants/:tenantId` | The caller has none of `ADMIN_ROLE`, `API_ROLE`, `M2M_ROLE`, `M2M_ADMIN_ROLE`, `SECURITY_ROLE`, `SUPPORT_ROLE`, `INTERNAL_ROLE`, `VIEWER_ROLE`, or `REVIEWER_ROLE`; `validateAuthorization` in `TenantRouter`'s `getTenantById` handler throws `unauthorizedError`. | Cannot happen — `AuthGuard` checks route `authLevels`, and every frontend UI role (`admin`, `support`, `api`, `security`, `reviewer`, `viewer`) is accepted by `getTenantById`. | — | — |
| `tenant-process` | `POST /tenants/:tenantId/attributes/verified/:attributeId` | The caller is not `ADMIN_ROLE`; `validateAuthorization` in `TenantRouter`'s `updateTenantVerifiedAttribute` handler throws `unauthorizedError`. | Cannot happen — `useProviderAgreementGetVerifiedAttributesActions` returns no actions unless `isAdmin`, so non-admin users cannot submit the update from the agreement page. | — | — |
| `tenant-process` | `POST /tenants/:tenantId/mails` | The caller is not `ADMIN_ROLE`; `validateAuthorization` in `TenantRouter`'s `addTenantMail` handler throws `unauthorizedError`. | Cannot happen — `PartyContactsSection` renders the _Modifica_ action only when `isAdmin`; the drawer's submit also requires `jwt.organizationId`. | — | — |
| `tenant-process` | `DELETE /tenants/:tenantId/mails/:mailId` | The caller is not `ADMIN_ROLE`; `validateAuthorization` in `TenantRouter`'s `deleteTenantMailById` handler throws `unauthorizedError`. | Cannot happen — no frontend service, hook, or control calls this DELETE endpoint; the contact drawer only updates mail with POST. | — | — |
| `tenant-process` | `POST /tenants/delegatedFeatures/update` | The caller is not `ADMIN_ROLE`; `validateAuthorization` in `TenantRouter`'s `updateTenantDelegatedFeatures` handler throws `unauthorizedError`. | Cannot happen — `DELEGATIONS` admits support as well as admin, but `DelegationsAvailabilitySection` renders _Modifica_ only when `isAdmin`. | — | — |
| `tenant-process` | `POST /tenants/:tenantId/attributes/certified` | The caller has neither `ADMIN_ROLE` nor `M2M_ROLE` nor `M2M_ADMIN_ROLE`; `validateAuthorization` in `TenantRouter`'s `addCertifiedAttribute` handler throws `unauthorizedError`. | Cannot happen — `TENANT_CERTIFIER` admits support, but `AssignAttributesTab` hides both the assignment button and drawer unless `isAdmin`. | — | — |
| `tenant-process` | `POST /tenants/:tenantId/attributes/certifiedDiscrete` | The caller has neither `ADMIN_ROLE` nor `M2M_ADMIN_ROLE`; `validateAuthorization` in `TenantRouter`'s `addCertifiedDiscreteAttribute` handler throws `unauthorizedError`. | Cannot happen — `TENANT_CERTIFIER` admits support, but `AssignAttributesTab` hides both the assignment button and drawer unless `isAdmin`. | — | — |
| `tenant-process` | `POST /tenants/attributes/declared` | The caller has neither `ADMIN_ROLE` nor `M2M_ADMIN_ROLE`; `validateAuthorization` in `TenantRouter`'s `addDeclaredAttribute` handler throws `unauthorizedError`. | Cannot happen — `DeclaredAttributesListItem` exposes declare/revoke actions only when `isAdmin`, and `SUBSCRIBE_PURPOSE_CREATE` is admin-only. | — | — |
| `tenant-process` | `POST /tenants/:tenantId/attributes/verified` | The caller has neither `ADMIN_ROLE` nor `M2M_ADMIN_ROLE`; `validateAuthorization` in `TenantRouter`'s `verifyVerifiedAttribute` handler throws `unauthorizedError`. | Cannot happen — `useProviderAgreementGetVerifiedAttributesActions` returns no actions unless `isAdmin`. | — | — |
| `tenant-process` | `DELETE /tenants/:tenantId/attributes/verified/:attributeId` | The caller has neither `ADMIN_ROLE` nor `M2M_ADMIN_ROLE`; `validateAuthorization` in `TenantRouter`'s `revokeVerifiedAttribute` handler throws `unauthorizedError`. | Cannot happen — `useProviderAgreementGetVerifiedAttributesActions` returns no actions unless `isAdmin`. | — | — |
| `tenant-process` | `DELETE /tenants/attributes/declared/:attributeId` | The caller has neither `ADMIN_ROLE` nor `M2M_ADMIN_ROLE`; `validateAuthorization` in `TenantRouter`'s `revokeDeclaredAttribute` handler throws `unauthorizedError`. | Cannot happen — `DeclaredAttributesListItem` renders its revoke action only when `isAdmin`. | — | — |

## `hyperlinkDetectionError`

Hyperlink not allowed.

| Process | BFF endpoint | When it happens | Reachable from the FE? | Steps to reproduce (UI) | Resolution steps |
| ------- | ------------ | --------------- | ---------------------- | ----------------------- | ---------------- |
| `tenant-process` | `POST /tenants/:tenantId/mails` | `validateNoHyperlinksSafe` throws `hyperlinkDetectionError` in `TenantService.addTenantMail` when `mailSeed.description` contains an `http://`, `https://`, or `www.` hyperlink. | **CAN HAPPEN** — `UpdatePartyMailDrawer` validates the email and note length but does not remove or reject hyperlink text; changing the email submits the note unchanged. | **Data precondition:** you are `admin` of tenant A and it has a contact email.<br>1. Go to `/aderente/anagrafica`.<br>2. In _Contatti_, choose _Modifica_.<br>3. Change _Indirizzo email ente (richiesto)_ to a different valid email and set _Note_ to `https://example.com`.<br>4. Choose _Aggiorna_. | 🟢 **Easy resolution**<br>1. Remove the hyperlink from _Note_.<br>2. Submit the contact update again. |
