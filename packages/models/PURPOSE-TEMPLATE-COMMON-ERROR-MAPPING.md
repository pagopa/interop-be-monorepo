# Common errors mapping

> **Not documented** (same for every endpoint, or never surfaced over HTTP):
> - Authentication: `jwtDecodingError`, `invalidClaim`, `missingHeader`, `missingRSAKey`, `jwkDecodingError`, `jwksSigningKeyError`, `tokenVerificationFailed`, `notAllowedPrivateKeyException`, `notAllowedCertificateException`, `notAllowedMultipleKeysException`, `missingRequiredJWKClaim`, `invalidJWKClaim`, `keyTypeNotAllowed`, `invalidPublicKey`, `invalidKeyLength`, `notAnRSAKey`, `badBearerToken`, `badDPoPToken`.
> - Middleware-only: `badRequestError`, `tooManyRequestsError`.
> - Infrastructure: `authenticationSaslFailed`, `genericError`, `thirdPartyCallError`, `tokenGenerationError`, `missingKafkaMessageData`, `kafkaMessageProcessError`, `htmlTemplateInterpolationError`, `pdfGenerationError`, `kafkaApplicationAuditingFailed`, `fallbackApplicationAuditingFailed`, `invalidSqsMessage`, `decodeSQSMessageError`, `pollingMaxRetriesExceeded`.
>
> Processes covered: `purpose-template-process`.

## `invalidContentTypeDetected`

The uploaded document has a content type that is not allowed.

| Process | BFF endpoint | When it happens | Reachable from the FE? | Steps to reproduce (UI) | Resolution steps |
| ------- | ------------ | --------------- | ---------------------- | ----------------------- | ---------------- |
| `purpose-template-process` | `POST /purposeTemplates/:purposeTemplateId/riskAnalysis/answers/:answerId/annotation/documents` | The BFF throws `invalidDocumentDetected` in `validateAndStorePDFDocument` when the uploaded file's MIME type is not `application/pdf`, before calling the process. | **CAN HAPPEN** — the edit page's `RHFSingleFileInput` has no PDF `accept` restriction or client-side content-type validation. | **Data precondition:** an editable draft has a saved answer annotation and no attached documents.<br>1. Go to `/fruizione/template-finalita/` and click _Gestisci bozza_.<br>2. Open _Analisi del rischio_ and click _Allega documentazione_ on the annotated answer.<br>3. Select a non-PDF file, such as a PNG, and click _Carica_. | 🟢 **Easy resolution**<br>1. Select a PDF document instead.<br>2. Click _Carica_ again. |

## `invalidPdfSignatureError`

The uploaded file is not a valid PDF.

| Process | BFF endpoint | When it happens | Reachable from the FE? | Steps to reproduce (UI) | Resolution steps |
| ------- | ------------ | --------------- | ---------------------- | ----------------------- | ---------------- |
| `purpose-template-process` | `POST /purposeTemplates/:purposeTemplateId/riskAnalysis/answers/:answerId/annotation/documents` | The BFF's `validateAndStorePDFDocument` accepts MIME type `application/pdf` but throws `invalidPdfSignatureError` when `isPdf` rejects the file contents; this happens before the process call. | **CAN HAPPEN** — the upload form accepts a file whose type is reported as PDF without checking that its contents are a valid PDF. | **Data precondition:** an editable draft has a saved answer annotation and no attached documents; have a corrupt or non-PDF file named with a `.pdf` extension so the browser reports `application/pdf`.<br>1. Go to `/fruizione/template-finalita/` and click _Gestisci bozza_.<br>2. Open _Analisi del rischio_ and click _Allega documentazione_ on the annotated answer.<br>3. Select the invalid `.pdf` file and click _Carica_. | 🟢 **Easy resolution**<br>1. Replace the file with a valid PDF.<br>2. Click _Carica_ again. |

## `eventConflictError`

| Process | BFF endpoint | When it happens | Reachable from the FE? | Steps to reproduce (UI) | Resolution steps |
| ------- | ------------ | --------------- | ---------------------- | ----------------------- | ---------------- |
| `purpose-template-process` | `PUT /purposeTemplates/:purposeTemplateId` | Concurrent `updatePurposeTemplate` calls read the same draft version and both call `eventRepository.createEvent`; `EventRepository.internalCreateEvent` throws `eventConflictError` when the second insert hits the stream/version uniqueness constraint. | **CAN HAPPEN** — two admins of the same tenant can edit the same draft in separate sessions and submit concurrently. | **Data precondition:** tenant A owns a draft; two `admin` users for tenant A open that same draft before either submits.<br>1. In both sessions, go to `/fruizione/template-finalita/` and click _Gestisci bozza_.<br>2. Change _Descrizione finalità (richiesto)_ in each session.<br>3. Click _Salva bozza e prosegui_ in both sessions at nearly the same time. | 🟢 **Easy resolution**<br>1. Reload the draft after the other save finishes.<br>2. Check the current values and submit the remaining change again. |
| `purpose-template-process` | `DELETE /purposeTemplates/:purposeTemplateId` | Concurrent `deletePurposeTemplate` calls read the same draft version and both call `eventRepository.createEvent`; `EventRepository.internalCreateEvent` throws `eventConflictError` on a duplicate stream/version insert. | **CAN HAPPEN** — two admins can select the same draft for deletion at nearly the same time. | **Data precondition:** tenant A owns a draft; two `admin` users for tenant A have the draft list open.<br>1. Go to `/fruizione/template-finalita/` in both sessions.<br>2. Open the row actions for the same draft and select _Elimina_ in both sessions at nearly the same time.<br>3. Confirm the activation in both sessions. | 🟢 **Easy resolution**<br>1. Reload the list after the first request completes.<br>2. Check the template's current state and retry only if it is still suspended. |
| `purpose-template-process` | `POST /purposeTemplates/:purposeTemplateId/archive` | Concurrent `archivePurposeTemplate` calls read the same template version and both call `eventRepository.createEvent`; `EventRepository.internalCreateEvent` throws `eventConflictError` on a duplicate stream/version insert. | **CAN HAPPEN** — the admin-only _Archivia_ action can be used by two tenant admins at nearly the same time. | **Data precondition:** tenant A owns a published or suspended template; two `admin` users for tenant A have the template list open.<br>1. Confirm the archiving in both sessions. | 🟢 **Easy resolution**<br>1. Reload the list after the first request completes.<br>2.
