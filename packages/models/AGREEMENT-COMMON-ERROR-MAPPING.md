# Common errors mapping

> **Not documented** (same for every endpoint, or never surfaced over HTTP):
> - Authentication: `badBearerToken`, `badDPoPToken`, `invalidClaim`, `jwtDecodingError`, `jwksSigningKeyError`, `missingHeader`, `missingRequiredJWKClaim`, `tokenVerificationFailed`.
> - Middleware-only: —
> - Infrastructure: `authenticationSaslFailed`, `decodeSQSMessageError`, `fallbackApplicationAuditingFailed`, `genericError`, `htmlTemplateInterpolationError`, `invalidSqsMessage`, `kafkaApplicationAuditingFailed`, `kafkaMessageProcessError`, `missingKafkaMessageData`, `missingRSAKey`, `pdfGenerationError`, `thirdPartyCallError`, `tokenGenerationError`.

> Processes covered: `agreement-process`.

## `invalidFileUploadError`

The uploaded file is not an allowed format or extension.

| Process | BFF endpoint | When it happens | Reachable from the FE? | Steps to reproduce (UI) | Resolution steps |
| ------- | ------------ | --------------- | ---------------------- | ----------------------- | ---------------- |
| `agreement-process` | `POST /agreements/:agreementId/consumer-documents` | The uploaded file fails `isValidFile` in the BFF's `AgreementService.addAgreementConsumerDocument`, for example a `.pdf` without a PDF signature. The BFF throws this before calling the agreement process. | **CAN HAPPEN** — `ConsumerAgreementDocsInputSection` uses `RHFSingleFileInput` without an `accept` restriction or PDF-content validation; the form checks only filename length and submits the selected file. | **Data precondition:** you are `admin` of tenant B and can edit B's draft agreement; have a file named `not-a-real.pdf` whose contents are not a PDF.<br>1. Open `/fruizione/richieste/{agreementId}/modifica` for the draft agreement.<br>2. In _Documentazione_, click _Carica il file_ and select `not-a-real.pdf`.<br>3. Enter at least five characters in _Nome documento_.<br>4. Click _Carica_. The BFF rejects the file because it has no PDF signature, although the form allows it to be submitted. | 🟢 **Easy resolution**<br>1. Select a valid PDF file.<br>2. Enter its _Nome documento_ and click _Carica_ again. |

## `eventConflictError`

The request conflicts with an ongoing operation on the same resource; retry it.

| Process | BFF endpoint | When it happens | Reachable from the FE? | Steps to reproduce (UI) | Resolution steps |
| ------- | ------------ | --------------- | ---------------------- | ----------------------- | ---------------- |
| `agreement-process` | `POST /agreements/:agreementId/submit` | Two submissions read the same agreement stream version and both try to append events; the losing `repository.createEvents` call in `AgreementService.submitAgreement` throws `eventConflictError` through `eventRepository`. | **CAN HAPPEN** — two authorized consumer admins can submit the same draft before the first update reaches the read model. | **Data precondition:** tenant B has two `admin` users; both can access the same draft agreement for an e-service owned by tenant A.<br>1. In two sessions, open `/fruizione/richieste/{agreementId}/modifica` for that draft.<br>2. In both sessions, click _Inoltra richiesta_ at nearly the same time. One request can append using the same stream version and fail with the conflict. | 🟢 **Easy resolution**<br>1. Reload the agreement and check its current state.<br>2. If it is still a draft, retry _Inoltra richiesta_ once. |
| `agreement-process` | `POST /agreements/:agreementId/approve` | Two approvals read the same agreement stream version; `AgreementService.approveAgreement` calls `performAgreementActivation`, whose `repository.createEvents` call throws `eventConflictError` through `eventRepository` for the losing write. | **CAN HAPPEN** — two provider admins can activate the same pending agreement while its first activation is still propagating. | **Data precondition:** tenant A has two `admin` users; agreement E is pending and A is its producer.<br>1. In two sessions, open `/erogazione/richieste/{agreementId}`.<br>2. In both sessions, click _Attiva_ and then _Conferma_ at nearly the same time. One event write can lose the stream-version race. | 🟢 **Easy resolution**<br>1. Reload the draft and check which document was saved.<br>2. Upload the missing document again. |
| `agreement-process` | `DELETE /agreements/:agreementId/consumer-documents/:documentId` | Two document removals read the same agreement stream version; `AgreementService.removeAgreementConsumerDocument` calls `repository.createEvent`, which throws `eventConflictError` through `eventRepository` for the losing write. | **CAN HAPPEN** — two consumer admins can remove documents from the same draft before either update reaches the read model. | **Data precondition:** tenant B has two `admin` users; the same draft agreement has at least two attached documents.<br>1.
