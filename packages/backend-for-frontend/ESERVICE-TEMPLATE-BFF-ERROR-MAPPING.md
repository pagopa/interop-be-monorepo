# BFF errors mapping

> **Not documented**:
> - Authentication: — (no error in `errors.ts` is raised while authenticating every request; errors from specific authentication endpoints remain documentable)
> - Infrastructure: `selfcareEntityNotFilled`, `attributeNotExists`, `dynamoReadingError`, `missingInterface`, `noDescriptorInEservice`, `missingDescriptorInClonedEservice`, `privacyNoticeVersionIsNotTheLatest`, `missingActivePurposeVersion`, `activeAgreementByEserviceAndConsumerNotFound`, `purposeIdNotProvided`, `cannotGetKeyWithClient`, `clientAssertionPublicKeyNotFound`, `delegatedEserviceNotExportable`, `noVersionInEServiceTemplate`, `delegationContractNotFound`
> - Unused (no throw site in the BFF): `eserviceIsNotDraft`, `invalidJwtClaim`, `eserviceTemplateIsNotPublished`, `tooManyDescriptorForInterfaceWithTemplate`, `eserviceTemplateInterfaceNotFound`, `invalidInterfaceFile`, `eserviceTemplateInterfaceDataNotValid`, `invalidEserviceInterfaceFileDetected`, `operationForbidden`
>
> Routers covered: `eserviceTemplateRouter`.

## `eserviceTemplateVersionNotFound`

The requested version was not found in the e-service template.

| Router | BFF endpoint | When it happens | Reachable from the FE? | Steps to reproduce (UI) | Resolution steps |
| ------ | ------------ | --------------- | ---------------------- | ----------------------- | ---------------- |
| `eserviceTemplateRouter` | `GET /eservices/templates/:eServiceTemplateId/versions/:eServiceTemplateVersionId` | `getEServiceTemplateVersion` calls `retrieveEServiceTemplateVersion`; the template returned by the e-service-template process does not contain the requested version ID. | **CAN HAPPEN** — the provider summary page fetches the draft version by its route ID. Another user in the same tenant can delete that draft while the first user's details page is still open, leaving its `Gestisci bozza` action stale. | **Data precondition:** Tenant A owns a template with a published version and a draft version. Two users with the Admin or API role in A can manage it. <br> 1. User A opens the template's published version from `I miei template e-service` and leaves the page open. <br> 2. In a separate browser, user B opens the same template, clicks `Elimina bozza`, then confirms the `Conferma cancellazione bozza` dialog with `Conferma`. <br> 3. Without refreshing user A's page, click the still-visible `Gestisci bozza` action. The summary page requests the now-deleted draft version; this is the defect step. | 🟡 **Medium resolution** — return to `I miei template e-service`, open the current version of the template, create a replacement draft with `Crea bozza da template`, and repeat any work that was only in the deleted draft. |
| `eserviceTemplateRouter` | `POST /eservices/templates/:eServiceTemplateId/versions/:eServiceTemplateVersionId/documents` | `createEServiceTemplateDocument` calls `retrieveEServiceTemplateVersion`; the template returned by the e-service-template process does not contain the requested version ID. | **CAN HAPPEN** — the version-document form takes its template and draft IDs from the loaded draft. A collaborator can delete that draft while the form remains open, and submitting the form uses the stale version ID. | **Data precondition:** Tenant A owns a template with a published version and a draft version. User A (Admin or API role) can edit it; user B (Admin or API role) can delete the draft. <br> 1. User A opens the template's published version from `I miei template e-service`, clicks `Gestisci bozza`, then `Modifica bozza` to open the draft editor. <br> 2. In a separate browser, user B opens the same template, clicks `Elimina bozza`, then confirms the `Conferma cancellazione bozza` dialog with `Conferma`. <br> 3. In user A's still-open editor, go to `Documentazione`; if documents are already listed, click `Aggiungi un altro file`. <br> 4. Select a file, enter its `Nome documento`, and click `Salva documento`. The request still carries the deleted draft's version ID; this is the defect step. | 🟡 **Medium resolution** — leave the stale editor, open the template's current version from `I miei template e-service`, create a replacement draft with `Crea bozza da template`, and upload the document to that draft. |

## `catalogEServiceTemplatePublishedVersionNotFound`

No published version was found in the catalog e-service template.

| Router | BFF endpoint | When it happens | Reachable from the FE? | Steps to reproduce (UI) | Resolution steps |
| ------ | ------------ | --------------- | ---------------------- | ----------------------- | ---------------- |
| `eserviceTemplateRouter` | `GET /catalog/eservices/templates` | `getCatalogEServiceTemplates` converts each result with `toBffCatalogEServiceTemplate`; the catalog-process response contains a template with no version in the `PUBLISHED` state, despite the request filtering for `PUBLISHED` versions. | **CAN HAPPEN (UNVERIFIED)** — entering the template catalog calls this endpoint, but the frontend cannot create the inconsistent result. It depends on the catalog-process response, for example a stale or inconsistent result during a publication-state change. | **Data precondition:** Tenant B owns a catalog entry that the catalog process returns for a `PUBLISHED`-state query, but its returned template has no `PUBLISHED` version. <br> 1. Sign in to tenant A with an Admin, API, Support, or Viewer role. <br> 2. Open `Catalogo dei template di e-service` (`/erogazione/catalogo-template`). The page loads the catalog automatically; the preconditioned result triggers the error. | 🔴 **Impossible resolution** — a user cannot repair the catalog-process result from this page. Ask the template owner or support to restore a published version or correct the inconsistent catalog data. |
